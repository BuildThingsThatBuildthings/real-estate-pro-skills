# Listing campaign

## Campaign reset and flagship dependency

For a complete listing suite, the primary production unit is a full flagship property film with a beginning, room-by-room progression, emotional payoff and invitation. A short motion test is internal shot validation only. After that test, generate the complete required footage library and finish the flagship; do not expand a proof into a tray of unrelated teasers while leaving the flagship absent. Build all requested films, graphics, recording scripts and copy from one private campaign story, claim ledger, shot library and deliverable inventory. Reusable skill code consumes those inputs; no listing facts belong in the shared implementation.

When the user requests deleting and rebuilding rejected outputs, their instruction overrides default preservation of rejected exports. Move only the explicitly rejected generated campaign packages to recoverable Trash, with a before/after record. Preserve the actual listing source media, business brand assets and research evidence. Rebuild the complete requested inventory; a single replacement film alone does not fulfill a complete campaign reset.

Source-image provider compatibility is handled by `scripts/prepare_source_images.py`. It converts authorized images to PNG with dimensions and provenance preserved; this is not image generation or a motion substitute.

Use this extension with `content-foundry`, `brand-voice`, `aia-listing-photos`, and `aia-neighborhood-story`. Private client facts and media belong in the run folder, never this skill. An approved user campaign plan authorizes its production; record that approval in BRIEF.md without repeating the approval request. The standard full campaign uses only bundled AIA capabilities and supplied original media. Do not impose new purchases, third-party sign-ins, credits, subscriptions or optional paid providers to complete this version. A missing capability must be reported honestly; it never lowers the required film quality.

For rejected creative, cinematic walkthroughs, or feedback that video feels like slides, first apply [creative recovery](references/creative-recovery.md). Prove the motion and voice direction before multiplying deliverables. Source-led supporting dollhouses follow [spatial diagrams](references/spatial-diagrams.md); they never count as measured scans or finished photographic walkthroughs.

## Run contract

Production run roots must use persistent private storage, never `/tmp`, `/private/tmp`, OS temporary folders or volatile scratch volumes. Initialize the dedicated folder with `scripts/run_storage.py init --root <persistent-private-folder> --run-id <fresh-id>` before authoring. A restart must not erase sources, source ledgers, narration or accepted exports. Keep this folder ignored by git. Temporary files are permitted only as regenerable scratch beneath an already durable run; unit fixtures explicitly use `scope: test` and cannot supply production evidence.

After a lost or reset run, use `run_storage.py inventory-source` and `restore` for exact surviving original assets and runtime/font dependencies. The recovery plan names allowed source roots, original/dependency basis, exact hashes and source/dependency destinations. The helper verifies both sides, refuses conflicting files and refuses old exports or generated narration as originals. Missing creative work must be authored and rendered again in the new run. Recovery receipts remain private; copying originals never counts as media production.

For a complete launch use `profile: full-listing-campaign`, a new `run_id`, and the mandatory inventory exported by `scripts/validate_campaign.py`. It includes full property/launch/neighborhood films, four property reels, a local reel, two alternate-opening edits, three teasers, 26 social graphics, video covers, a QR image and the requested useful document kit. The flagship's spatial camera treatment belongs inside the property film. A full campaign cannot opt out of this profile to pass validation.

Explicit full-reset instructions override preservation of rejected versions. Use `scripts/reset_campaign.py inventory` with verified destination IDs, preserve supplied originals, record the existing user authorization privately, then execute and verify removal. Remove all generated work in the authorized scope regardless of perceived quality. Keep framework folders and use recoverable Trash. A partial API listing is a failed reset check. Local/provider-generated assets also require scoped cleanup. No new creative generation begins while the required reset is unresolved.

Media folders contain MP4/PNG/JPG only. Requested PDFs, six agent scripts, listing/outreach copy, platform captions and the posting sequence belong in designated document folders. JSON, SRT/VTT, logs, manifests, internal research ledgers, editor projects and verification receipts never upload to client Drive, including Weekly Context. Use embedded captions. Production implementation state remains private.

Create `run.json` with client_slug, brand, approval, sources, claims, media, deliverables, and stages. Each claim has id, text, source_ids, verified_at, status (verified, conflicting, historical, unresolved). Each source has id, url, retrieved_at, and supporting excerpt or artifact. Each medium has id, path/url, source_id, rights (authorized, licensed, original, unresolved), rights_basis, commercial_use, license_evidence, location, and fidelity_review. Each deliverable has id, kind, required, status (planned, rendering, awaiting_footage, failed, review, complete), path, claim_ids, media_ids, and review evidence. Never substitute a storyboard or preview for a required finished film.

1. **Context and identity.** Sync the current client context. Read the agent's own professional writing before agency-written website copy. Verify name, brokerage, contact, logo, color and font against the current client sources. Run Content Foundry dependency checks. Do not import the operator's branding.
2. **Research.** Follow [research and voice](references/research-voice.md). Keep historical facts separate from current listing facts. Build claim and media ledgers before writing copy.
   Inspect the current listing's media controls for an existing 3D tour, 360 panoramas, floor plan and photographer video before commissioning generated motion. Record whether each actually loads, its provenance and permitted reuse. A visible tour button is a discovery lead, not acquired footage or a completed walkthrough. Existing source tours can establish spatial continuity even when exports require the owner or photographer.
3. **Creative direction.** Write BRIEF.md: central premise, distinct angles, emotional progression, coordinated visual/spoken/written hooks, precise output list, palette, typography, music direction, costs, evidence boundaries. Lock before generation. Use the existing user approval when it covers this brief.
4. **Production.** Follow [motion and edit](references/motion-edit.md). Delegate the neighborhood narrative to `aia-neighborhood-story`. Compose horizontal and vertical separately. Use real source photos and verified local imagery; maps may be original diagrams clearly labeled with their limitations.
   For photograph-led static designs, `scripts/render_photo_designs.py` consumes explicit private layer/crop/type decisions and records source hashes, rights and actual text boxes. Inspect a representative design before rendering its siblings. Its receipt proves rendering, not brand or creative approval.
5. **Agent kit.** Follow [recording and delivery](references/recording-delivery.md). Future recordings are awaiting_footage. Scripts do not count toward finished video totals.
6. **QA.** Run `python scripts/validate_campaign.py run.json`. Run Content Foundry compliance, brand and slop gates. Fully review every export with audio, then muted; document reviewer, time, issues and fixes. Technical probes and frame samples support but never replace full viewing. Verify actual footage against originals. No assumed or self-certified full-playback pass.
7. **Delivery.** Send only finished, explicitly selected deliverables through Content Foundry's delivery gate into the authorized listing subfolder under Waiting. Weekly Context remains input/source context; never upload a run directory there. Verify filenames, downloaded bytes, embedded captions, playback and QR destination. Evidence stays private. Use copy/upload for delivery; explicit reset uses the separate scoped deletion workflow. Never publish or schedule.
   After upload, run `scripts/verify_drive_delivery.py` with the local folder, remote, parent folder ID, destination and a receipt outside the checked folder. It downloads and compares every delivered file; a mismatch or missing file fails. This checks transfer integrity only. Playback, captions, QR destination and creative acceptance remain separate checks.

## Continue independent production

Track dependencies per required deliverable. A missing bundled production capability or destination-media license blocks only assets that depend on it. Do not route around a missing capability by proposing an optional paid tool, a new account or a sign-in. Continue all ready graphics, copy, agent scripts, editing and evidence work. Keep the entire requested output inventory in `run.json`; do not reduce scope to a proof clip, count tests as finished films, or end the run merely because one provider failed. Resume at the first unfinished dependency-ready item. The campaign is incomplete while any required asset is unfinished, even if all currently executable work is done. When the user selects the bundled basic-editor route, produce complete original-photo films with controlled framing, varied timing, narration and visual progression. Review the actual edited film; do not call it generated camera footage or a measured 3D walkthrough. The full flagship and all required edits remain mandatory.

Use `scripts/run_workflow.py workflow.json` for local production tasks. Each task names its governing AIA skill, explicit dependencies, argv command, expected files and status. The runner logs actual execution and hashes outputs, continues independent branches after failures, and leaves manual review/access tasks open. Only tasks in `executed` satisfy dependencies; this state does not mean the deliverable passed creative QA. Keep provider submissions and account approvals out of automatic retry loops.

Production tasks require an installed AIA script entrypoint and private consumed-input receipt. The runner binds current run and skill/script hashes, validates actually consumed originals or same-run producer outputs, and refuses stale outputs/execution states. Provider or human operations need actual tool/job evidence through their governing skill; writing a status field is insufficient. Resume only this run's evidenced work. Completed film reviews bind the exact output hash and private sound/muted evidence; these records do not automate aesthetic judgment.

## Portability evidence

Run validator tests and a second clearly fictional fixture with different brand, geography, home type and narrative. It must refuse unresolved sources/rights and an incomplete required film. Never place fixture facts in client media. Report behavioral evidence and remaining limits; a schema-only test is not full creative portability proof.

## Available local narration

`local_narration.py` supports an Apache-licensed Kokoro ONNX model with a built-in synthetic voice. Record model/voice source, license, runtime version and file hashes in the private run. Install its runtime in an isolated environment and keep weights outside git. A short successful audition precedes a batch. Scene-level time fitting must stay within the specified speed ceiling; caption timing and pronunciation still need full playback review. Use `final_mix.py` to map only source video and approved sound, excluding all rejected evaluation audio.

## Runtime dependencies

Production dependencies are required for a requested full campaign and isolated from the lightweight evidence gate. Use Python 3.11 or newer for production scripts, FFmpeg/FFprobe, the existing Remotion engine Node dependencies, Pillow, fonttools with Brotli, qrcode, and ReportLab. Local narration additionally needs kokoro-onnx and its supported ONNX runtime. Record the tested versions in each run; do not install model weights or client media in the skill repository. The evidence validator and its test suite remain dependency-light and run in CI.
